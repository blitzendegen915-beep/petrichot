# new-article

`affiliate/content/` に記事を1本追加し、ビルド確認して公開する手順。引数でトピック指定があればそれを使い、なければ既存記事と重複しないトピックを選ぶ。

## 記事タイプの決定

1. `affiliate/content/*.md` の frontmatter を確認し、category「AIをはじめて学ぶ」の記事数を数える。
2. 教育記事が全体の1/3未満なら**教育記事**、以上なら**ツール紹介記事**を書く(引数指定があれば優先)。

- **ツール紹介記事**: AIツールの比較・使い方・活用術。`affiliate/links.json` の既存IDから1〜2個選び、`{{aff:ID}}` を紹介直後やまとめ前など自然な位置に**単独行**で挿入。category はツール比較/業務効率化/デザイン等。
- **教育記事**: 中高生向けAIリテラシー・学習活用・社会とAI。やさしい言葉、上から目線にならない口調。category: `AIをはじめて学ぶ`。`{{aff:ID}}` を1個、記事内容に合う自然な位置に挿入する(2026-07-19よりオーナー指示で全記事広告ありに変更)。

## frontmatter スキーマ(厳守)

```
---
title: 記事タイトル(30字前後)
description: メタディスクリプション(80〜110字)
slug: lowercase-ascii-hyphens
date: YYYY-MM-DD(今日)
category: カテゴリ名
tags: [タグ1, タグ2, タグ3]
---
```

## 本文ルール

- **3000〜6000字**の自然な日本語。導入 → `##` 見出し → `## まとめ` → `## 参考リンク`。
  ※ 旧基準は1500〜2500字だったが、浅すぎるため2026-08-02に改定した。
- **本文に `#`(h1)を書かない**(タイトルはテンプレートが出す。書いてもビルドが降格/除去するが、最初から書かない)。
- 比較にはGFM表(`| a | b |` + 区切り行)が使える(ビルドが変換)。
- 誇大表現・断定的な収益/効果保証は禁止。料金・モデル名などは断定を避け「2026年時点」等でぼかす。
- 記事末尾に必ず `## 参考リンク`(2〜4個)。**URLは承認済みリストのみ(捏造厳禁)**:
  openai.com/chatgpt/, claude.ai, gemini.google.com, www.notion.com/product/ai, www.canva.com, www.midjourney.com, github.com/features/copilot, www.perplexity.ai, openai.com, www.anthropic.com, blog.google/technology/ai/, www.soumu.go.jp/johotsusintokei/whitepaper/, www.mext.go.jp, www.ipa.go.jp

## 記事の厚みの基準(2026-08-02新設・lintが機械で検査する)

**このサイトの弱点は「見出しだけ多くて各節が薄い」ことだった。**書く前にこの節を読むこと。

| 基準 | 数値 | lintの挙動 |
|---|---|---|
| 本文の分量 | 3000〜6000字 | 2500字未満でWARN |
| 1見出しあたり | **400字以上** | 見出し5個以上で平均400字未満ならWARN |
| 表・図・箇条書き | どれか1つは必須 | 全て無ければWARN |

### 見出しを増やすより、1つの節を厚くする

見出しを10個並べて各300字にするより、**見出し5〜7個で各600〜800字**のほうが良い記事になる。
1つの節には、最低でも次のどれかを入れる:

- **具体的な場面**「経費精算のレシート読み取りを任せた場合」のように、業務や生活の場面で書く
- **そのまま使える指示文**(コピペできる形。汎用の言い換えではなく、条件まで書いた実物)
- **判断基準の表**(向く/向かない、任せる/任せない、AがよいときとBがよいとき)
- **失敗の戻し方**(うまくいかなかったとき何をするか)

### やってはいけない厚みの作り方

- 同じことを言い換えて伸ばす(水増し)
- 一般論を並べる(「AIは便利です」「使い方が重要です」)
- 前置きと注意書きを長くする

**読者が読んだあとに何かできるようになっているか**が基準。字数はその結果であって目的ではない。

### 図(SVG)を使ってよい

```svg キャプション
<svg viewBox="0 0 640 200" xmlns="http://www.w3.org/2000/svg" role="img">...</svg>
```
の形で図を入れられる(ビルドが処理する)。色は `var(--accent)` `var(--fg)` `var(--muted)` `var(--border)` `var(--surface-2)` を使う。
比較・手順・分類は、文章で説明するより図のほうが伝わる。

## 書いてはいけないこと(捏造対策・最重要)

過去に実在する調査会社名を使った存在しない統計が混入した。以下は **`node affiliate/lint.mjs` がERRORで弾く**:

- **「〇〇の調査によると」「〇〇のレポートでは」など、出典を第三者に帰属させる記述**
- **調査会社・シンクタンク名の言及**(Gartner / IDC / McKinsey / 野村総研 など)
- 成果を約束する表現(「確実に達成」「必ず実現」「保証します」)
- 誇大表現(「最強」「圧倒的」「劇的に」「誰でも簡単」「完全無料」)
- 参考リンクに文書名を書くこと(実在確認ができない。**サイト名のみ**書く)

また lint が**警告**する数値は、書く前に「その数字の出どころを言えるか」を自問すること:
効果のパーセンテージ、料金、所要時間、削減率は**原則書かない**。「公式サイトでご確認ください」に逃がす。
指示役から具体的な数値を渡された場合のみ、その範囲で書いてよい。

## ビルド・公開

1. **`node affiliate/lint.mjs affiliate/content/<新記事>.md` — ERRORが0件になるまで直す。** 警告は内容を目視で確認。
2. `node affiliate/build.mjs` — エラー・警告ゼロ、記事数+1を確認。
3. **`git reset --hard` は使わない**(未pushの作業を破壊しうる)。`git add` は新規記事ファイルのみ個別指定(`-A`/`.`禁止)。
4. **`affiliate/build.mjs` は触らない**(レビュー待ちの未pushの変更がある)。
5. commit(`auto: 新規記事「<タイトル>」を追加`)→ `git push origin main`。
6. push後1〜2分で `git ls-remote origin gh-pages` のハッシュが変わればデプロイ成功。

**サブエージェントとして呼ばれた場合**: 上記2〜5は行わない。記事ファイル作成と`node affiliate/build.mjs`での検証までを行い、パスと結果を報告して終了する(commit/pushは指示役が行う)。
