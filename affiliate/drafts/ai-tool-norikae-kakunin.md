AIツールは、使っているうちに「合わない」と感じる場面が出てきます。回答の雰囲気が自分の仕事に合わない、扱いたい種類の作業が変わった、別のツールのほうが気になる、といった理由はどれも自然なものです。

ただ、乗り換えは「新しいものを契約して、古いものをやめる」だけでは終わりません。保存したプロンプトや過去のやり取り、共有したリンク、チームの習慣など、手元の作業に染みついたものが一緒に動くからです。何も確認せずに切り替えると、数週間後に「あの設定、どこにいったのか」と探すことになりがちです。

この記事では、乗り換えを考えたときに確認する点を、順番に整理します。複数のツールを契約しすぎて整理したい場合は、別の記事[AIツールの契約が増えすぎたときの整理のしかた](/ai-tool-keiyaku-seiri/)が向いています。ここでは「ひとつのツールから別のツールへ移る」場面に絞って扱います。特定の製品の機能や料金には触れません。ChatGPTやClaudeのような対話型のAIを、乗り換えの例として思い浮かべながら読んでください。細かい仕様は、それぞれの公式サイトで確認してください。

## 乗り換えたい理由を先に分けて考える

最初にやるのは、乗り換えたい理由を言葉にすることです。理由によって、確認すべきことが変わるからです。

| 乗り換えたい理由 | 先に確かめること |
|---|---|
| 出力が自分の用途に合わない | 指示文の書き方で改善できないか。同じ指示を別のツールに渡して比べたか |
| 作業の種類が変わった | 新しい作業を、今のツールの別の機能やモードで済ませられないか |
| 契約の条件や規約が変わった | 変更の内容を公式の案内で読んだか。自分の使い方に影響があるか |
| 新しいツールが気になる | 今のツールで困っていることは何か。気になる理由は具体的か |
| 周囲のチームが別のツールを使い始めた | 一緒に使う必要がある範囲はどこまでか |

この表を見ると分かるように、「出力が合わない」と感じているときは、乗り換えの前にできることがあります。指示文に背景や条件が足りないだけで、ツールの問題ではないケースもあるからです。指示文の見直しは、乗り換えより先に試す価値があります。

一方で、規約の変更やチームの都合が理由であれば、ツールの出力の良し悪しは関係なく、乗り換えが妥当な判断になることもあります。理由を一行で書き出し、「それは指示文の工夫で解決する話か、ツールを替えないと解決しない話か」を分けてください。この一手間で、不要な乗り換えを減らせます。

## 手放す前に、持ち出すものを棚卸しする

乗り換えを決めたら、古いツールの中に何が入っているかを書き出します。次の項目を順に確認してみてください。

- 過去の会話の履歴(あとで読み返したいものはあるか)
- 保存したプロンプトやテンプレート
- 自分用に設定した指示(口調、立場、出力の形式など)
- 作成した文書や画像などの成果物
- 共有したリンクや、他の人が見ているページ
- 他のサービスとの連携設定(カレンダー、ノート、チャットなど)
- 契約者情報と請求に関する情報

履歴や成果物を書き出せるかどうか、どんな形式で出せるかは、サービスごとに違います。ここは推測で進めず、公式のヘルプで確認します。書き出す機能が見当たらない場合は、必要なものだけ手作業で別の場所に写すことになります。

写すときのコツは、全部を移そうとしないことです。履歴はたいてい量が多く、読み返すものは一部です。「また使いたい指示文」「手直しして仕上げた成果物」「参考にした出力例」に絞って、ひとつのフォルダかノートにまとめておくと、新しいツールでもすぐに使い始められます。

また、設定した指示は意外に忘れやすい項目です。自分で書いた指示は、そのまま新しいツールに貼り付けられるよう、テキストとして控えておきます。控えがあれば、設定の入力場所が違っても再現できます。

## 期間を決めて、同じ課題で並べて試す

新しいツールを契約したら、すぐ古いものをやめるのではなく、並べて使う期間を決めます。期間の長さは、普段の作業の頻度に合わせて決めてください。週に数回しか使わない人が数日で判断すると、材料が足りなくなります。

比べるときは、普段の仕事から課題を選びます。たとえば次のようなものです。

- 長めの文章の要約
- 相手に送るメールの下書き
- 箇条書きのメモを文章に整える
- 調べものの下調べ

同じ課題を、同じ指示文で、両方のツールに渡します。指示文を変えると、比較の意味がなくなります。次のような記録表を作って、結果を並べて見るとよいでしょう。

```
課題:
指示文:
ツールA の結果(気づいたこと):
ツールB の結果(気づいたこと):
手直しにかかった手間(少ない・普通・多い):
そのまま使えたか(はい・一部・いいえ):
```

評価は、点数ではなく「手直しの手間」で書くのがコツです。点数は人によって基準がぶれますが、手直しの手間は自分の作業に直結します。世の中のランキングや点数より、自分の課題での結果を優先してください。

## 切り替えで崩れやすいのは、チームの習慣

自分ひとりで使っているなら、ここまでの確認でほぼ足ります。しかし、チームや家族、教室などで共有しているツールを替える場合は、もうひとつ確認が要ります。ツールそのものより、周りの使い方が崩れやすいからです。

確認したいのは、次のような点です。

- 共有しているテンプレートやプロンプト集が、新しいツールで同じように使えるか
- 誰がどの範囲で使うか(権限、アカウントの管理者)
- 古いツールで作った成果物を、誰が参照しているか
- 切り替えの日程と、その連絡の方法
- 困ったときに聞ける人はだれか

うまくいったプロンプトの共有の仕組みについては、[うまくいったプロンプトをチームで共有する仕組み](/prompt-team-kyouyuu/)で扱っています。共有の置き場所がツールの中にしかないと、乗り換えのたびに作り直しになります。ツールの外に、共通のノートや文書として置いておくと、移行の負担が下がります。

もうひとつの落とし穴が、切り替えの周知です。「来週から新しいツールを使います」だけでは、使い方が各自バラバラになります。最初の1〜2週間は、古いツールを残したまま、「どの作業からどちらを使うか」を決めて伝えておくと、混乱が小さくなります。

## 解約・削除の前に確かめること

並行して試した結果、乗り換えると決めたら、古いツールの解約に進みます。ここで確認したいのは、次の4点です。

1. 更新日と請求のタイミング。次の更新の前に手続きが必要か
2. 解約すると、保存した履歴や成果物がどうなるか(すぐ消えるのか、一定期間残るのか)
3. 解約とアカウント削除が別の手続きかどうか
4. 共有リンクや連携が、解約後に使えなくなるか

どれも、公式のヘルプや利用規約に書かれています。規約のどこを読めばよいかについては、[AIの利用規約はどこを読めばいい?](/ai-riyoukiyaku-yomikata/)が手がかりになります。また、入力した内容の扱いが変わるかどうかは、乗り換え先でも同様に確認してください。確認の方法は[AIに入力した内容は学習に使われる?確認方法を知ろう](/ai-nyuryoku-gakushuu-riyou/)にまとめています。

解約したあとに「やっぱり戻りたい」と思うことも、ありえます。その場合に備えて、書き出したデータと自分用の指示文を、しばらく手元に残しておくと安心です。削除は、新しいツールで一通りの作業を回してからで遅くありません。

## まとめ

AIツールの乗り換えで確認する点を整理すると、次の流れになります。

- 乗り換えたい理由を言葉にして、指示文の工夫で足りるかを先に確かめる
- 履歴、保存した指示文、成果物、共有リンク、連携を書き出して、持ち出すものを決める
- 期間を決め、同じ課題と同じ指示文で並べて試し、手直しの手間で比べる
- チームで使う場合は、共有物の置き場所と切り替えの連絡を決める
- 解約の前に、更新日、データの扱い、アカウント削除の手続きを公式の情報で確認する

乗り換えは、早くやるほど良いものではありません。確認のための手間は、あとで探し物をする手間より小さく済みます。慌てずに、順番に進めてください。
