見積書や請求書は、数が増えるほど手間になる書類です。文面を毎回考えるのが面倒で、AIに下書きを手伝ってほしいと思うのは自然なことです。

ただ、この種の書類は、金額、宛名、日付といった間違えてはいけない項目が集まっています。しかも、取引先に出すもので、お金の請求や契約に関わります。この記事では、AIを使う範囲と、人が自分で見る範囲を分け、送る前に確認する点を整理します。制度や書式の細かい決まりは変わることがあるため、公式の情報で確認してください。

## AIに任せる部分と、人が決める部分を分ける

最初に決めておくのは、どこまでをAIに任せるかです。見積書や請求書の中身は、性質の違う部分が混ざっています。

| 部分 | 例 | AIの役割 |
|---|---|---|
| 文面・言い回し | 送付状、添え書き、お礼や支払いのお願いの文 | 下書きを任せやすい |
| 構成の確認 | 項目の並べ方、抜けている記載がないかの点検 | 確認の補助に使える |
| 金額・数量 | 単価、数量、合計、税の扱い | 人が計算して決める |
| 宛名・日付 | 取引先名、担当者名、発行日、支払期限 | 人が元の資料から転記する |
| 取引条件 | 支払条件、納期、有効期限、修正対応 | 人が合意内容から書く |

分け方の基本は、「間違えたときの影響が大きいものは、人が決める」です。文面の言い回しが少し不自然でも、取引は成り立ちます。しかし、金額や宛名が違えば、請求の誤りや、相手との信頼の問題になります。

特に、AIは計算が苦手な場面があります。数字を並べた合計や、税の計算を任せると、もっともらしい数字が間違って出てくることがあります。この性質については、[AIが苦手なこともある｜数え間違い・計算・長い手順での確かめ方](/ai-nigate-kazoeru-keisan/)で説明しています。合計は、AIではなく、表計算ソフトや会計の道具で計算し、AIの計算結果は使わないようにします。

つまり、AIには「文を書く」「点検する」役を頼み、「決める」「計算する」役は人に残す、という分担です。

## 入力する情報を選ぶ

見積書や請求書には、取引先の名前や金額など、外に出したくない情報が多く含まれます。AIに依頼するときは、入力する内容を、必要最小限にします。

入力の判断を、表にまとめます。

| 情報 | 扱い |
|---|---|
| 取引先の正式名称・住所・担当者名 | 入れない。下書きの「宛名」「会社名」といった仮の表記に置き換える |
| 実際の金額・単価 | 入れない。「金額」「数量」の枠だけを伝える |
| 口座番号などの振込先 | 入れない。下書き後に人が書き込む |
| 取引の内容(どんな仕事か) | 一般的な言い方に直してから入れる |
| 自社の名称・肩書 | 方針に従う。迷ったら入れない |

具体的な情報を入れなくても、文面の下書きは作れます。「宛名」「金額」などの仮の言葉を入れておいて、下書きができあがってから、人が実際の情報に置き換えればよいのです。

使うサービスによって、入力した内容の扱いが違います。入力が学習に使われるか、どのくらいの期間保存されるかなどは、サービスごとに設定や規約を確認します。確認方法は[AIに入力した内容は学習に使われる?確認方法を知ろう](/ai-nyuryoku-gakushuu-riyou/)に、情報の入力に関する考え方の基本は[AIと個人情報|入力していいこと・ダメなこと](/ai-to-privacy-kojinjouhou/)にまとめています。

職場で使う場合は、会社や取引先の決まりが優先されます。契約の中で、情報の取り扱いが定められていることもあるので、確認しておきます。

## 下書きを頼む依頼文の例

実際の依頼は、仮の表記を使った形にします。次の例は、請求書に添える文面の下書きを頼むものです。

```
請求書を送るときの添え書きの文面を作ってください。

条件:
- 相手は、取引のある会社の担当者
- 丁寧だが、簡潔な文面にする
- 宛名の部分は「(宛名)」、金額の部分は「(金額)」、期限の部分は「(支払期限)」と仮の表記にする
- 請求内容は「(業務の概要)」と仮の表記にする
- 最後に、不明点があれば連絡してほしい旨を入れる
- 金額や日付を、自分で作らない
```

最後の「金額や日付を、自分で作らない」という一文が重要です。AIは、指示がないと、もっともらしい数字や日付を補ってしまうことがあります。仮の表記のまま出力させ、人が埋める運用にすれば、混入を防げます。

見積書の添え書きの場合は、有効期限や、条件の変更に関する一文を入れてもらうことが考えられます。内容は取引ごとに違うので、AIの案を参考に、自分の言葉で調整します。

書類の構成を点検してもらう使い方もあります。たとえば、次のように頼みます。

```
見積書に一般的に記載される項目を、チェックリストの形で挙げてください。
そのうえで、私が今作っている書類に、足りない項目がないか確認するための質問を作ってください。
```

AIが挙げた項目は、あくまで一般的な例です。法律や制度で求められる記載事項は、税や制度の公式の情報で、別に確認する必要があります。ここは、AIの答えを根拠にしてはいけない部分です。

## 送る前の最終チェック

下書きができたら、送る前に人が確認します。確認の観点を、順番に並べます。確認する順番を決めておくと、見落としが減ります。

1. 宛名は正しいか(会社名の表記、部署、担当者名、敬称)
2. 発行日は正しいか(今日の日付になっているか。月や年が古いままではないか)
3. 品目と数量は、取引の内容と一致しているか
4. 単価と合計は、電卓や表計算で再計算して合っているか
5. 税の扱いは、自社と相手の取り決めに合っているか(制度は公式の情報で確認)
6. 支払期限と振込先は、取引の条件と一致しているか
7. 文面に、AIが勝手に足した約束(納期、保証、割引など)が混ざっていないか
8. 自社の名称、住所、連絡先は正しいか

七番目は、特に見落としやすい点です。AIは、丁寧な文面を書こうとして、「迅速に対応いたします」「責任をもって対応します」といった約束めいた表現を加えることがあります。実際にそれが可能か、約束してよいかを、人が判断します。

書類の確認は、書いた本人だけでなく、別の人が見る体制があると安心です。一人で運営している場合は、一日おいて見直すだけでも、気づける誤りが増えます。

AIが事実と違うことを書く仕組みは、[AIはなぜもっともらしい嘘をつくのか](/ai-hallucination-naze/)で解説しています。書類に限らず、AIの出力を確認する習慣の土台になります。

## 記録と、次回に向けた整え方

最後に、うまく回すための工夫をまとめます。

書類の下書きの依頼文は、一度うまくいったものを保存しておくと、次回から再利用できます。仮の表記を使う形式なら、取引先が変わっても、そのまま使えます。依頼文を「見積書の添え書き用」「請求書の添え書き用」「支払いのお願い用」のように、種類別に整理しておくと便利です。

また、確認でミスを見つけたときは、記録を残します。たとえば、「日付を前月のまま送りそうになった」「宛名の敬称が違っていた」といった内容です。これを溜めると、自分の弱点が見え、確認の優先順位を決める材料になります。

書類のやり取りが増えてきたら、専用の会計や請求の道具を検討する段階かもしれません。道具の機能や制度への対応は変わるため、導入前に公式の情報を確認してください。

## まとめ

見積書や請求書にAIを使うときは、文面の下書きや構成の点検に使い、金額、宛名、日付、取引条件は人が決めます。合計の計算はAIに任せず、表計算などで行います。依頼するときは、取引先名や金額を仮の表記にして、実際の情報は入れません。

送る前には、宛名、日付、品目、金額、税、支払条件、そしてAIが足した約束の有無を順に確認します。制度や書式の決まりは、公式の情報で確かめます。AIは手間を減らす道具ですが、書類の責任は、出す人にあります。
