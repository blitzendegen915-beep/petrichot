会議のあとに時間がかかるのは、議事録の清書より、「結局、誰が何をやるのか」を整理する作業ではないでしょうか。話は盛り上がったのに、終わってみると担当も期限も曖昧で、次の会議で同じ話をやり直す。そんな経験はありませんか。

この記事では、会議の文字起こしからAIに「やること」を抜き出してもらう手順を紹介します。議事録全体のまとめ方ではなく、会議のあとに動くための項目に絞った話です。AIが抜き出した結果には抜けや誤りがあり得るため、確認の方法もあわせて説明します。

## 議事録と「やることの一覧」は別物

まず、議事録と、やることの一覧は、役割が違うことを整理しておきます。

| 項目 | 議事録 | やることの一覧 |
|---|---|---|
| 目的 | 何が話され、何が決まったかを残す | 会議の後に誰が何をするかを明確にする |
| 読む人 | 参加者、欠席者、後から確認する人 | 担当者本人と進行役 |
| 形 | 文章や箇条書きの記録 | 担当・内容・期限を持つ項目の並び |
| 残す期間 | 長く保管することが多い | 完了したら役目を終える |

議事録を丁寧に作っても、やることが埋もれていれば、会議のあとに動きにくくなります。反対に、やることの一覧だけがあっても、なぜそうなったかが分からなくなります。両方が必要ですが、作る手順は分けて考えたほうが楽です。

AIを使うなら、まず文字起こしをもとにやることを抜き出し、その結果を議事録の末尾に添える、という順序が扱いやすくなります。議事録そのものの作り方は、[AI議事録・メモ術で会議を効率化](/ai-gijiroku-memo-jutsu/)で解説しています。この記事は、その続きとして読めます。

## 準備｜録音と文字起こしを用意する

AIにやることを抜き出してもらうには、元になる文字起こしが必要です。会議の内容を文字にする方法は、手で書き起こす、録音を文字起こしの道具に通す、などがあります。

録音して文字起こしにつなげる道具には、いくつかの種類があります。録音して文字起こしにつなげる道具の一例として、Notta Memoがあります。機能や対応範囲、料金などの細部は変わることがあるため、公式サイトで最新の情報を確認してください。

{{aff:notta-memo}}

録音を使う場合は、事前に参加者の同意を取ることが前提です。何を確認しておくべきかは、[会議をAIで録音する前に確認しておきたいこと](/kaigi-rokuon-mae-kakunin/)にまとめています。

文字起こしができたら、AIに渡す前に、次の下ごしらえをしておくと結果が安定します。

- 参加者の名前を、先頭に一覧で書いておく(誰の発言か判断しやすくなる)
- 会議の日付と議題を、冒頭に書いておく
- 明らかな誤変換(人名、社名、専門用語)があれば、手早く直しておく
- 個人情報や社外秘が含まれるなら、伏せ字にするか、使ってよいツールかを確認する

文字起こしの精度が低くて困るときの対処は、[AI文字起こしがうまくいかないときの直し方](/ai-mojiokoshi-seido-kaizen/)で扱っています。人名や固有名詞の誤りは、そのままだと担当者が間違ってしまうので、特に念入りに確認します。

## 手順｜依頼文で「やること」を抜き出す

下ごしらえができたら、AIに依頼します。大切なのは、抜き出したい項目の形を、あらかじめ指定することです。形を指定しないと、AIは要約のような文章で返してくることがあります。

次の依頼文は、そのまま使えます。かっこの部分を差し替えてください。

```
以下は会議の文字起こしです。この中から「会議のあとに誰かが行動するべきこと」だけを抜き出してください。

出力は次の表の形にしてください。
| 内容 | 担当者 | 期限 | 根拠となった発言 |

ルール:
- 担当者が文字起こしから特定できない場合は「不明」と書く
- 期限が述べられていない場合は「未定」と書く。推測で日付を作らない
- 「検討する」「考えておく」のような曖昧な発言は、別の表「保留の事項」に分ける
- 根拠となった発言は、文字起こしの該当部分をそのまま短く引用する

【参加者】(名前の一覧)
【会議の日付】(日付)
【文字起こし】
(ここに貼る)
```

この依頼文には、三つの工夫があります。

一つ目は、「不明」「未定」と書かせることです。AIは、指示がないと空欄を埋めようとして、担当者や期限を推測で書くことがあります。分からないものは分からないと書かせるほうが、あとの確認が楽になります。

二つ目は、「保留の事項」を分けることです。会議では「やってみよう」「考えておきます」といった発言が多く出ます。これらを同じ表に入れると、実際に動くべきことが見えにくくなります。

三つ目は、「根拠となった発言」を引用させることです。この列があれば、AIの抜き出しが正しいか、元の発言と照らして確かめられます。

## 確認｜AIの抜き出しを鵜呑みにしない

AIが出した表は、そのまま共有してはいけません。会議の出席者の目で確認するようにします。確認の観点は次のとおりです。

| 確認の観点 | 見ること |
|---|---|
| 抜け | 会議で決まったのに、表に載っていないことはないか |
| 担当者 | 名前が合っているか。「不明」の項目を、誰かが埋められるか |
| 期限 | 発言と一致しているか。AIが日付を補っていないか |
| 勝手な追加 | 会議で言われていないことが、項目に混ざっていないか |
| 保留の扱い | 保留にした項目が、実は決定事項ではないか |

有効な確認方法は、「根拠となった発言」の列を、元の文字起こしと一つずつ照らすことです。手間はかかりますが、共有したあとの訂正を減らせます。

とくに注意が必要なのは、担当者の取り違えです。会議の中で「私がやります」と言ったのが誰か、文字起こしだけでは分からない場面があります。その場合は、会議に出ていた人に確認し、表を直します。

AIの抜き出しに間違いが混ざる理由は、[AIはなぜもっともらしい嘘をつくのか](/ai-hallucination-naze/)で説明しています。表がきれいに整っていることと、中身が正しいことは別だと覚えておいてください。

## 共有｜会議の直後に出して、確認してもらう

やることの一覧は、時間がたつほど価値が下がります。記憶が新しいうちに共有して、参加者に確認してもらうのが理想です。

共有の流れは、次のようにします。

1. 会議が終わったら、できるだけ早く文字起こしを作る
2. AIで抜き出し、自分で元の発言と照らして修正する
3. 参加者に、表を送る。「間違いがあれば返信してください」と添える
4. 修正を反映し、確定版として共有の場所に置く
5. 次の会議の冒頭で、前回のやることの進み具合を確認する

三番目の「間違いがあれば返信してください」が重要です。担当者本人が確認できれば、取り違えを早期に直せます。返信がなければ承認とみなす、といった運用を、あらかじめチームで決めておくと、止まりません。

送るときの文面は、短く構いません。

```
本日の会議のやることを整理しました。
ご自身の担当と期限に間違いがないか、ご確認ください。
修正があれば、返信でお知らせください。
```

そして、次の会議の冒頭で、前回の表を見返す習慣をつけます。やることの一覧は、作って終わりではなく、次の会議で進み具合を確認して初めて役に立ちます。

## まとめ

議事録からやることを抜き出すときは、議事録とは別の目的の一覧として扱います。文字起こしの下ごしらえをし、表の形と「不明」「未定」の書き方を指定して依頼します。出てきた表は、根拠の発言と元の文字起こしを照らして、人の目で確認します。

そのうえで、会議の直後に共有して、担当者本人に確認してもらいます。AIは、整理の手間を減らす道具ですが、抜けや取り違えを防ぐ役目は人に残ります。まずは次の会議で、依頼文をそのまま試してみてください。
