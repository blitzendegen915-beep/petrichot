社内報、オウンドメディア、採用記事、顧客事例。取材やヒアリングをして記事にまとめる仕事では、「話を聞くこと」と「メモを取ること」が同時に起こります。メモに気を取られると相手の目を見て聞けず、聞くことに集中するとあとで細部を思い出せません。AIによる録音と文字起こしは、この板挟みをやわらげる手段の一つです。

ただし、録音して文字にすれば原稿ができるわけではありません。録る前の同意、文字起こしの誤りの確認、発言の要約と引用の区別、公開前の本人確認、録音データの扱い。この流れを順に踏まないと、あとで相手との信頼を損なうことがあります。この記事では、取材の前から原稿の公開前までを、そのまま使える文例つきで手順に分けて説明します。会議の録音全般については「[会議をAIで録音する前に確認しておきたいこと](/kaigi-rokuon-mae-kakunin/)」も合わせてご覧ください。

## 全体の流れと、AIに任せる範囲

最初に、取材記事づくりの流れと、どこまでをAIに任せてどこから人が判断するのかを整理します。

| 段階 | AIに任せやすいこと | 人が必ず行うこと |
|---|---|---|
| 録音前 | なし | 目的と使い道の説明、同意の取得 |
| 録音中 | 録音と文字起こしの下準備 | 相手の話を聞く、深掘りの質問 |
| 文字起こし後 | 文字化、話者ごとの整理 | 固有名詞と数字の確認 |
| 要点整理 | 話題ごとの分類、要約の下書き | 発言の意図が合っているかの判断 |
| 原稿化 | 構成案と文章の下書き | 事実関係と表現の最終判断 |
| 公開前 | なし | 取材相手への確認、修正の反映 |
| 公開後 | なし | 録音データの保存・削除 |

表のとおり、AIが力を発揮するのは文字化と下書きの部分です。「相手が何を言いたかったのか」「この表現を載せてよいか」という判断は、人の仕事として残ります。AIの出力は、あくまで人が確認する前の材料だと位置づけておくと、手順の組み立てがしやすくなります。

## 録音前に同意を取る手順と説明の文例

録音は、始める前に相手の同意を取ってからにします。取材の依頼の段階で伝えておき、当日にもう一度、口頭で確認するのが基本です。当日いきなり切り出すと、断りにくい空気を作ってしまうからです。

説明で伝えたいのは次の4点です。

- 何のために録音するのか(記事の正確さのため、など)
- 録音と文字起こしにAIのサービスを使うこと
- 録った内容をどの範囲の人が見るか
- 公開前に原稿を確認してもらうことと、データをいつ消すか

依頼メールの一文は、たとえば次のように書けます。

```
当日は、記事の内容を正確にまとめるため、お話を録音させていただければと思っております。
録音はAIによる文字起こしに使用し、記事の作成が終わりましたら、
社内の取り決めに沿って削除いたします。
原稿は公開前に必ずご確認いただきます。
録音にご不安がある場合は、メモのみでの取材も可能ですので、遠慮なくお申し付けください。
```

当日の口頭では、短くこう言います。

```
先ほどメールでもお伝えしましたが、記事を正確にまとめるために録音させてください。
文字起こしにはAIを使います。録音したものは記事ができたら削除します。
途中で「ここは止めてほしい」という箇所があれば、いつでも言ってください。
```

大切なのは、断れる選択肢を実際に用意しておくことです。「録音してもよろしいですよね」という聞き方では、同意ではなく圧力になります。断られたときはメモだけで進め、録音を前提にした進行にしないようにします。また、録音を止めてほしいという申し出があった箇所は、その部分を原稿にも載せないのが原則です。

社内報で同僚に取材する場合も、同じ手順を省かないほうが安全です。社内だから気軽に録れると考えず、相手が上司や他部署の人であっても、目的と使い道を先に説明します。

## 録音環境の準備と、録音する道具の例

文字起こしの正確さは、録音の質に大きく左右されます。AIがどれだけ進歩しても、聞き取れない音声は正しく文字にできません。取材の前に、次の点を整えておきます。

- 静かな部屋を選ぶ。空調や外の音が入りにくい場所にする
- 話す人の間に録音機器を置き、全員の声が同じくらいの距離で入るようにする
- 紙をめくる音や机を叩く音が入りにくい配置にする
- 本番の前に短く試し録りをして、声が入っていることを再生して確かめる
- 電池や保存の空き容量を、前日までに確認しておく

オンライン取材の場合は、相手のマイクの状態が音質を決めます。事前に「イヤホンマイクを使っていただけると聞き取りやすくなります」と伝えておくと、あとの確認作業が減ります。

録音の道具としては、スマートフォンの録音アプリのほか、録音と文字起こし、要約までを一つの流れで扱えるAIボイスレコーダーがあります。たとえばPlaudは、録音して文字起こしや要約につなげる道具の一例です。機能や対応する言語、料金などの詳細は変わることがあるため、公式サイトで確認してください。道具ごとの違いは「[AIボイスレコーダー比較|議事録・メモを自動化](/ai-voice-recorder-hikaku/)」でも整理しています。

{{aff:plaud}}

道具を選ぶときは、機能の多さよりも、取材相手に説明しやすいかどうかを基準にすると失敗が少なくなります。録ったデータがどこに保存され、誰が見られるのかを自分の言葉で説明できない道具は、取材には向きません。

## 文字起こしの誤りを確かめる方法

文字起こしの結果は、読みやすい文章の形で出てきます。そのため、誤りがあっても気づきにくいのが落とし穴です。確認が必要なのは、とくに次の項目です。

| 確認する項目 | 起こりやすい誤り | 確かめ方 |
|---|---|---|
| 人名・社名・商品名 | 同音の別の漢字、似た名前への置き換え | 名刺、公式サイト、事前資料と照合する |
| 数字・日付・金額 | 桁や単位の取り違え、聞き落とし | 録音を再生して該当箇所を聞き直す |
| 専門用語・略語 | 一般的な言葉への置き換え | 用語集や相手の資料と見比べる |
| 否定の言い回し | 「ない」「できる」の取り違え | 前後の文脈ごと音声で確認する |
| 話者の区別 | 発言者の取り違え | 録音の該当箇所を聞いて確かめる |

進め方としては、まず文字起こし全体を一度通して読み、意味が通らない箇所に印を付けます。そのうえで、印を付けた箇所と、固有名詞・数字の箇所だけを、録音を再生しながら照合します。全部を聞き直すより、確認の対象を絞るほうが現実的です。

AIは、聞き取れなかった部分をそれらしい言葉で補ってしまうことがあります。文脈に合って自然に見える箇所ほど、誤りが紛れ込みやすいと考えてください。数字と固有名詞は、原稿に載せる前に必ず元の資料か音声で裏を取ります。

文字起こしの精度が思うように出ないときの対処は、「[AI文字起こしがうまくいかないときの直し方](/ai-mojiokoshi-seido-kaizen/)」にまとめています。

録音から文字起こしまでを手軽にそろえたい場合は、Nottaの録音用デバイスであるNotta Memoのような道具もあります。録音して文字起こしにつなげる道具の一例として挙げるもので、対応する機能や条件は公式サイトでご確認ください。

{{aff:notta-memo}}

どの道具を使っても、確認の手順は変わりません。道具が文字にしてくれるのは「聞こえた音」であり、「相手が言いたかったこと」ではないからです。

## 要約と原稿の下書きをAIに頼む依頼文

文字起こしを確認したら、AIに要点の整理と下書きを頼みます。ここで気をつけたいのは、AIが発言にない内容を足したり、言い回しを自然に整えすぎて意味が変わったりしないようにすることです。依頼文に条件を書き込んでおくと、このずれを減らせます。

要点整理の依頼文の例です。

```
以下は、社内報の記事のための取材の文字起こしです。
次の条件で、話題ごとに要点を整理してください。

- 話題ごとに見出しをつけ、その下に要点を箇条書きにする
- 取材相手が実際に言ったことだけを書く。推測や補足は加えない
- 数字、日付、人名、社名は、文字起こしに書かれているとおりに残す
- 意味がはっきりしない箇所は、推測で直さず「要確認」と書く
- 印象的な発言は、一字も変えずに「」で抜き出して別にまとめる

【文字起こし】
(ここに貼り付ける)
```

要点を整理したあと、原稿の下書きを頼むときは、次のように続けます。

```
上の要点をもとに、社内報向けの記事の下書きを書いてください。

- 読者は社内の他部署の社員。専門用語には短い説明を添える
- 「」で囲んだ部分は、取材相手の発言をそのまま引用したものとして扱う
- 地の文は、発言の内容を言い換えた要約として書く
- 要点にない事実や評価は書かない
- 確認が必要な箇所には【要確認】と付ける
```

出てきた下書きは、そのまま使わずに、元の文字起こしと見比べます。見るべきは、要点にない話が混ざっていないか、相手の主張の強さが変わっていないか、という2点です。「検討している」と言った話が「取り組んでいる」と書き換えられているような変化は、気づかないまま公開してしまうと取り返しがつきません。

## 引用と要約の区別、公開前の本人確認

記事の中では、**相手の発言をそのまま載せる引用**と、**内容をまとめ直した要約**を、はっきり区別して書きます。カギ括弧で囲んだ部分は、相手が実際に話した言葉であるべきです。AIが整えた文章を、カギ括弧に入れて載せることは避けます。

話し言葉をそのまま載せると読みにくい場合は、「えーと」などの言いよどみを取る程度の整え方にとどめます。意味や語尾の強さまで変える場合は、カギ括弧を外して要約の地の文に直します。引用のカギ括弧を付けるのは、相手が本人の言葉として確認した部分だけにするのが安全です。

公開前には、必ず取材相手に原稿を確認してもらいます。確認を依頼するメールは、次のように書けます。

```
お忙しいところ恐れ入ります。取材記事の原稿ができましたので、ご確認をお願いいたします。

- 事実関係、数字、お名前や社名の表記に誤りがないか
- 「」で示した部分が、ご発言の趣旨と合っているか
- 公開してはいけない内容が含まれていないか

修正のご希望は、該当の箇所に印をつけてお知らせください。
確認いただいた内容を反映したうえで、公開いたします。
```

顧客事例や採用記事のように、会社の名前や立場が表に出る記事では、本人だけでなく先方の広報や上長の確認が必要になる場合もあります。誰の承認があれば公開してよいのかを、取材の依頼の時点で相手に聞いておくと、公開直前に止まることを防げます。

## 録音データの保存・削除ルールを決める

録音データと文字起こしのテキストには、相手の声や、未公開の情報が含まれています。記事が公開されたあとも手元に残しておくと、それだけ流出や誤った共有のリスクを抱え続けることになります。取材を始める前に、次のような取り決めを決めておきます。

| 決めること | 決め方の例 |
|---|---|
| 保存場所 | 共有フォルダ全体ではなく、担当者と確認者だけが開ける場所に置く |
| 見られる人 | 原稿づくりに関わる人に限る |
| 削除の時期 | 原稿の確認が済んだら削除する、など期限を決める |
| 残すもの | 公開した原稿と、確認の記録だけを残す |
| AIサービスへの入力 | 載せてはいけない情報(機密、個人情報)を事前に決める |

削除の時期は、取材相手に最初に伝えた内容と必ず一致させます。「記事ができたら削除します」と伝えたのなら、そのとおりに実行します。削除したことは、チーム内の記録に残しておくと、あとで説明を求められたときに答えられます。

また、AIサービスに音声や文字起こしを入力すると、データが外部のサーバーで処理されます。サービスごとにデータの扱いの方針が異なるため、利用前に公式サイトの説明を読み、社内の情報管理のルールと照らして確認してください。情報セキュリティの考え方の基本は、IPA(情報処理推進機構)のサイトでも公開されています。

## まとめ

取材の記録をAIで残す手順を、順に振り返ります。

1. 録音の前に、目的・AIの利用・見る人・削除の時期を伝え、断れる形で同意を取る
2. 静かな場所で録り、試し録りで声が入っていることを確かめる
3. 文字起こしは、固有名詞と数字を中心に、録音か元の資料と照合する
4. 要約と下書きは、条件を書いた依頼文で頼み、元の文字起こしと見比べる
5. 引用と要約を区別し、カギ括弧は実際の発言にだけ付ける
6. 公開前に取材相手の確認を取り、修正を反映する
7. 録音データは、決めた期限で削除する

AIがしてくれるのは、記録と下書きの手間を減らすことです。相手との約束を守ることと、内容に責任を持つことは、これまでどおり人の仕事です。まずは次の取材の依頼メールに、録音の説明の一文を加えるところから始めてみてください。
