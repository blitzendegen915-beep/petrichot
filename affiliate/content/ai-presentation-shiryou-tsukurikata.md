プレゼン資料を作っていて、時間を取られるのはどこでしょうか。話す内容そのものより、**体裁を整える工程**だと感じることがあります。文字の大きさをそろえる、図の位置を調整する、色を統一する。中身が決まっていても、見た目を整えるだけで半日が消えることがあります。

この工程は、AIを使ったデザインツールで短くできる部分です。ただし、体裁を整えるより前に「誰に何を伝えるか」が決まっていないと、どんなツールを使っても資料はぼやけます。この記事では、社内発表や勉強会の資料を作る会社員・学生の方に向けて、AIでプレゼン資料を作るとはどういうことか、発表の骨組みをどう作るか、どこまで任せてどこを自分で決めるかを、実務の順番に沿って整理します。

## AIでプレゼン資料を作るとはどういうことか

「AIが資料を作る」と聞くと、丸ごと全部やってくれる印象を持つかもしれませんが、実際に効いているのは主に次の3つです。

**1. たたき台の生成**
伝えたいことを文章で入力すると、スライドの構成案や下書きが出てきます。白紙から始める必要がなくなり、「直す作業」に持ち込めます。

**2. テンプレートの適用**
配色、文字の大きさ、余白といったデザインの決まりごとが、あらかじめ用意されています。デザインの知識がなくても、破綻しない見た目になります。

**3. 体裁の自動調整**
文字量が変わったときの配置調整など、手作業だと地味に時間がかかる部分をまとめて処理してくれます。

つまりAIが引き受けているのは、**判断がいらない反復作業**です。何を伝えるかという中身は、依然として人が決めます。

手作業で作る場合と比べると、違いは次のようになります。

| | 手作業で作る | AIツールを使う |
|---|---|---|
| 作りはじめ | 白紙から構成を考える | 下書きを直すところから始まる |
| デザイン | 自分で配色や余白を決める | テンプレートに沿う |
| 得意なこと | 独自性の高い表現 | 決まった形の資料を数多く |
| 苦手なこと | 時間がかかる | 型から外れた表現 |

比べて見えてくるのは、**AIツールは「量」に強く、手作業は「特別な1枚」に強い**ということです。毎週の定例報告や、似た形の提案書を何本も作る場面ではAIツールが効きます。一方、勝負をかける1本のプレゼンなら、時間をかけて自分で作る価値があります。

似た性格のツールとして、スライド作成に特化した[イルシルでAIスライド資料を作る方法](/irusiru-ai-slide-tsukurikata/)や、資料全般を扱う[Canva AI（Magic Studio）の使い方｜初心者が失敗しにくい指示文と手順](/canva-ai-design-nyumon/)も記事にしています。ツールそのものを選ぶ段階であれば、[AI資料作成ツールの選び方｜作り方のタイプで決める](/shiryou-sakusei-tool-erabikata/)が判断の助けになります。

## 発表の骨組みを先に作る｜依頼文の実物

ツールを開く前に決めておきたいのは、発表の骨組みです。骨組みとは、**聞き手は誰か、持ち時間はどれだけか、聞き終えた人にどうなってほしいか**の3点から導く、話の順番のことです。この骨組みをAIと一緒に作ると、白紙の状態から抜け出しやすくなります。

たとえば、社内の定例会で新しい社内ツールの試用結果を報告する場面を考えます。聞き手は課長と同じチームの先輩で、持ち時間は短く、質疑の時間も必要です。このとき、次のような依頼文を渡します。かぎ括弧の中は、自分の状況に書き換えて使ってください。

```
社内発表の資料の骨組みを作ってください。スライドの中身はまだ書かなくて構いません。

【聞き手】「部署の課長と、同じチームの先輩3人。ツールの専門知識はない」
【持ち時間】「発表8分、質疑2分」
【発表の目的】「試用結果を共有し、来月から正式に使うかどうかの判断材料にしてもらう」
【聞き終えたあとに取ってほしい行動】「正式導入の可否を、次の定例会までに決めてもらう」
【手元の材料】「試用した期間、試した業務の一覧、うまくいった点と困った点のメモ」

次の形式で出してください。
1. 発表全体を一言で言うとどうなるか(1文)
2. スライドの順番(1枚ごとに「そのスライドで言いたいこと」を1文で)
3. 持ち時間に対して枚数が多すぎないか、あなたの見立て
4. 聞き手が最初に抱きそうな疑問を3つ

材料にない事実や数字は作らず、足りない情報は「要確認」と書いてください。
```

この依頼文のポイントは3つあります。1つ目は、**聞き手と持ち時間を最初に書く**ことです。同じ内容でも、専門家に向けた十分な時間の発表と、非専門家に向けた短い報告では、省くところも厚くするところも変わります。2つ目は、**スライドの中身ではなく「言いたいこと」を1文ずつ出させる**ことです。骨組みの段階で本文まで出させると、直す量が増えます。3つ目は、**材料にない事実を作らせない**と明記し、足りないところは「要確認」と書かせることです。これでAIが数字をそれらしく埋める事態を減らせます。指示文の組み立て方全般は[AIへの指示文(プロンプト)の書き方基本ガイド](/prompt-no-kakikata-kihon/)にもまとめています。

出てきた骨組みは、そのまま採用せず、次の順で見直します。

1. 「発表全体を一言で言うと」の1文が、自分の言いたいことと合っているか
2. 持ち時間に対して枚数が多すぎないか。多ければ、削るスライドを自分で選ぶ
3. 聞き手の疑問に、発表の中で答えているスライドがあるか

学生の発表でも同じです。聞き手を「同じ研究室のメンバー」「他分野の参加者」のように具体的に書きます。うまくいかなかったときは、出てきた構成を直そうとせず、**聞き手の書き方を具体的にして出し直す**ほうが早く済みます。

## 1枚に1つのメッセージ、話す原稿は別に作る

骨組みができたら、スライドを作る段階に入ります。ここで守りたいのは、**1枚のスライドには1つのメッセージだけ**という考え方です。「このスライドで言いたいこと」を1文で言えないなら、そのスライドは2枚に分けるか、削る候補です。

骨組みの段階で出した「そのスライドで言いたいこと」の1文は、そのままスライドのタイトルの候補になります。「試用結果」のような名詞だけの見出しより、「入力作業の手間は減ったが、確認作業は残る」のように、**結論が読める文**にしておくと、聞き手は画面を見ただけで要点をつかめます。

スライドに載せる文字は、聞き手が話を聞きながら読める量に絞り、細かい説明は原稿の側へ回します。

つまり、**資料と話す原稿は別物**として扱います。資料は聞き手が見るもの、原稿は自分が話すためのものです。1つの文書に両方を詰め込むと、スライドは文字だらけになり、発表者は画面の文章を読み上げるだけになります。

AIには、スライドの内容を渡して、次のように原稿を作らせると使えます。

```
次のスライドの内容をもとに、口頭で話す原稿のたたき台を作ってください。

【聞き手】「課長と先輩。専門用語は避けたい」
【このスライドで言いたいこと】「入力作業の手間は減ったが、確認作業は残る」
【スライドに載せている内容】「(スライドの箇条書きをここに貼る)」
【話す長さの目安】「持ち時間を枚数で割った長さ。ゆっくり話して収まる量」

スライドに書いていない事実や数字は足さず、足りない情報は「要確認」と書いてください。
文末は話し言葉にして、読み上げて不自然な箇所があれば指摘してください。
```

原稿ができたら、必ず**声に出して読みます**。書き言葉のまま作った原稿は、読んでみると息が続かない箇所や、言いにくい言い回しが見つかります。そこを自分の言葉に直すと、発表者自身が内容を理解して話している状態に近づきます。

持ち時間に収まらないときは、原稿を速く読むのではなく、**スライドを減らす**のが基本です。図で伝えたい箇所については、[AIで図解を作るときの現実的な進め方](/ai-zukai-sakusei/)も参考になります。

文言とメッセージが固まったら、体裁の仕上げにテンプレート型のツールを使います。MiriCanvasのように無料で登録できるものなら、手元のスライドで試してから判断できます。

## MiriCanvasという選択肢と、使う前のアカウント設定

MiriCanvasは、テンプレートを土台にプレゼン資料やデザインを作れるサービスです。無料で登録できるプランがあるため、まず触ってから判断できます。骨組みと原稿のたたき台ができたあと、体裁を整える段階で、こうしたテンプレート型のツールが役に立ちます。

どんなテンプレートがあるか、どこまで無料で使えるか、有料プランとの違いがどうなっているかは、変更されることがあります。**必ず公式サイトで最新の内容を確認してください。**

{{aff:miricanvas}}

使いはじめる前に済ませておきたいのが、アカウントの安全面の設定です。デザインツールのアカウントには、作った資料が保存されます。仕事で使えば、社外に出していない企画や、顧客向けの提案内容がそこに溜まっていきます。

ここで役に立つのが**二次認証**です。二次認証とは、IDとパスワードだけでなく、**もう一段階の確認を加えて本人かどうかを確かめる仕組み**のことです。メールに届いた確認コードを入力する、といった形が一般的です。**パスワードが漏れただけでは入られない状態**にしておく意味は大きいです。

設定できる認証の方法や手順は、サービスによって異なります。登録の途中で案内が出たり、公式のヘルプに説明があったりしますので、最新の内容は公式のヘルプで確認してください。あとから設定しようと思うと、後回しになりがちです。登録のタイミングで済ませてしまうのが確実です。

会社の資料を扱う場合は、そもそも社内の規則でそのツールの利用が認められているかも先に確認してください。AIツール全般に言えることですが、入力した内容の扱いも一度確認しておくと安心です。この点は[AIに入力した内容は学習に使われる?確認方法を知ろう](/ai-nyuryoku-gakushuu-riyou/)でまとめています。

## AIに任せる部分と、自分で決める部分

ここまでの内容を、任せる部分と自分で決める部分に分けて整理すると、次の表のようになります。

| 作業 | AIに任せやすい | 自分で決める |
|---|---|---|
| 発表の目的と聞き手 | 選択肢を出させる | 最終的に何を伝えるかの決定 |
| 話の順番 | 骨組みのたたき台 | 採用する順番、削るスライド |
| スライドの文言 | 言い換え、短縮の案 | 結論の言い切り方 |
| 体裁(配色・余白・文字サイズ) | テンプレート適用、自動調整 | 全体を見ての最終確認 |
| 話す原稿 | 話し言葉のたたき台 | 声に出して直す、自分の言葉にする |
| 数字・固有名詞・出典 | 書式の整理 | 元データとの突き合わせ |
| 画像・イラストの使用 | 候補の提案 | 使ってよいかの確認 |

右の列は、責任を取るのが発表者である以上、人に残る部分です。以下、とくに大事な3つを説明します。

**数字と固有名詞**
売上、日付、社名、担当者名。AIは文章として自然な形を作るのが得意なので、**もっともらしい間違いが混じります**。資料に載せる数字は、必ず元データと突き合わせてください。この性質については[AIはなぜもっともらしい嘘をつくのか](/ai-hallucination-naze/)で説明しています。

**相手に合わせた調整**
同じ提案でも、現場の担当者と決裁者では刺さる話が違います。誰に見せるかによる調整は、相手を知っている人にしかできません。

**言い切るかどうかの判断**
「効果があります」と書くか「効果が期待できます」と書くか。この差は、後で責任の所在に関わります。ここは人が決めるべきです。

## 発表前の確認｜数字・出典・画像の権利

資料が仕上がったら、発表の前に確認の時間を取ります。確認する項目は、次の3つに絞れます。

**1. 数字**
資料に出てくる数字を、すべて書き出します。それぞれについて、元になった資料(社内の集計表、論文、公式の発表など)を開き、**数字・単位・期間**が一致しているかを見ます。AIに文章を整えさせたあとは、とくに注意が必要です。言い換えの過程で、「約」「以上」「平均」のような言葉が抜けたり、単位が変わったりすることがあります。元データが見つからない数字は、資料から外すか、「社内の感覚では」のように、根拠の弱さが伝わる書き方に変えます。

**2. 出典**
他人の調査や文章を引用している箇所には、出典を載せます。AIが「〜という調査があります」と書いた場合、その調査が実在するかを自分で確認してください。実在を確かめられないものは載せません。発表の場で「その出典は?」と聞かれたとき、答えられないのは発表者です。

**3. 画像・イラストの権利**
スライドに入れる画像は、使ってよいものかを確認します。自分で撮った写真、社内で用意された素材、使用条件が明示されたツール内の素材などは、条件の範囲で使えます。一方、検索で見つけた画像を、出どころを確かめずに貼るのは避けます。AIが生成した画像についても、使い方に条件がある場合があります。社外に出る資料や公開される発表では、とくに、ツールの利用規約を確認してください。

確認は発表の前日までに済ませ、最後に声に出して通して読み、持ち時間に収まることも確かめます。

確認で誤りが見つかったときは、その箇所だけを直して終わりにせず、**同じ元データから作った他のスライドにも影響がないか**を見ます。1つ数字が違っていれば、同じ元から転記した別の数字も疑う必要があります。

## まとめ

- AIが引き受けているのは、下書きの生成・テンプレートの適用・体裁の自動調整
- 決まった形の資料を数多く作る場面で効き、勝負の1本では手作業に分がある
- 聞き手・持ち時間・聞き終えた人の行動を書いた依頼文で、発表の骨組みを先に作る
- 1枚のスライドには1つのメッセージ。話す原稿は資料とは別に作り、声に出して直す
- 数字・固有名詞・相手への調整・言い切りの判断は人が引き受ける
- 発表前に、数字・出典・画像の権利を確認する
- 使う前に二次認証を設定しておく。資料が溜まるアカウントほど効果が大きい

資料作成にかかる時間のうち、体裁を整える部分は短くできます。空いた時間を「何を伝えるか」と「発表前の確認」に回せるかどうかが、実際の差になります。まずは次の発表で、聞き手と持ち時間を書いた依頼文から始めてみてください。
