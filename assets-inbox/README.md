# assets-inbox — 外部エージェント(Codex等)からの受け渡し場所

画像などの成果物を、このリポジトリに入れるための受け口です。
**ここに置かれたものは、検査を通るまでサイトには反映されません。**

## 使い方(渡す側)

1. ファイルを `assets-inbox/` 直下に置く
2. `assets-inbox/manifest.json` に、置いた全ファイルの項目を書く
3. コミットして push する

`manifest.json` の形式は `manifest.example.json` を見てください。

## 使い方(受け取る側)

```
node affiliate/check-assets.mjs
```

これが通ってから `affiliate/static/` へ移します。落ちた場合は理由が出ます。

## 決まりごと

### 全ファイルが manifest.json に載っていること

載っていないファイルがあれば検査は落ちます。「いつの間にか増えていた」を防ぐためです。

### 形式と容量

| 項目 | 制限 |
|---|---|
| 拡張子 | `.png` `.jpg` `.jpeg` `.webp` `.svg` |
| 1ファイル | 500KB まで |
| ファイル名 | 半角英数・ハイフン・アンダースコア・ドットのみ |

容量を絞っているのは、画像が重いとページの表示速度が落ち、
それがそのまま検索順位に効いてくるためです。

### SVGはスクリプトを含められない

`<script>`、`on*=` のイベントハンドラ属性、`javascript:` URL、
図形以外のタグが入っていると落ちます。

SVGはHTMLとしてそのままページに埋め込まれます。
つまり**外部から受け取ったSVGは、そのまま実行されうるコード**です。
記事本文の ```svg ブロックと同じ検査をここでも掛けています。

### 出典とライセンスを必ず書く

`manifest.json` の各項目に `source` と `license` が要ります。空欄は落とします。

- **自分で描いた/生成した場合** — `source: "generated"`、`license` に使ったツール名
- **どこかから持ってきた場合** — `source` に取得元URL、`license` にライセンス名

他人の著作物を、出所が分からないままサイトに載せると、
後から差し替えでは済まない問題になります。
**分からないものは入れない**でください。

### 人物の顔写真・企業ロゴは入れない

肖像権と商標の判断が別途必要になります。必要なときは個別に相談してください。
