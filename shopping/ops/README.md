# 楽天比較記事の運用

Petrichor Shoppingの調査、商品確認、比較記事、公開前原稿を管理します。記事を量産する前に、1テーマずつ次の順で進めます。

1. `rakuten_researcher` が需要の根拠と競合の比較軸を調査する
2. オーナーが記事化するテーマを1件選ぶ
3. `product_verifier` がメーカー・楽天市場の一次情報を照合する
4. `comparison_writer` が比較記事案を作る
5. `editor_publisher` が採点し、X・楽天ROOMの公開前原稿を作る
6. オーナーが実体験、商品リンク、変動情報を確認する
7. オーナーの明示承認後にだけ公開・予約操作へ進む

## 現在の初回テーマ

- ジャンル: 旅行用品
- 記事: 1〜3泊向け機内持ち込みスーツケース
- 主な比較軸: 機内持ち込み条件の確認、フロントオープン、キャスターストッパー、荷物量とのバランス
- 想定読者: 国内旅行・出張で短期用スーツケースを探す20〜40代
- 主な悩み: 「機内持ち込み可」と書かれていても航空会社・路線・機材・運賃種別などで条件が変わり、サイズと機能を決めきれない

検索ボリューム、売上、レビュー数、価格、在庫の確認データはまだ登録していません。初回ページは比較軸と確認手順の実装見本であり、商品別アフィリエイトリンクと本人の体験は公開前の入力待ちです。

## 保存先

- `research/YYYY-MM-DD.md` — 需要根拠、競合分析、記事候補
- `verified-products/<theme>.md` — 一次情報を照合した商品資料
- `drafts/YYYY-MM-DD-<theme>-案N.md` — 比較記事案
- `social/` — X投稿の公開前原稿
- `room/` — 楽天ROOMの公開前原稿
- `reports/` — 採点、差し戻し、テスト結果

各フォルダは最初に成果物を作る時点で作成します。空フォルダだけを増やしません。

## 実行例

```text
rakuten_researcherに、旅行用品の候補を3件、検索数を推測せず需要の代替指標と競合比較軸つきで調べてもらって。公開や保存先外への送信はしないで。
```

```text
product_verifierに、選んだスーツケース候補のメーカー公式情報と楽天市場の商品情報を照合させて。価格・在庫・ポイントは確認日時つきにして。
```

```text
comparison_writerに、検証済み資料だけを使って記事案を作らせて。未登録の体験は指定のプレースホルダーにして。
```

```text
editor_publisherに採点と差し戻し判定をさせ、合格した場合だけX 5案とROOM 3案を公開前原稿として作らせて。
```
